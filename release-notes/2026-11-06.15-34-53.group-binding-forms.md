**Breaking:** any `command_group(...)` call that isn't the whole value of a module-level assignment or bare statement now fails the manifest build with "unsupported command declarations", and so does `CommandsTester`. That covers a tuple or chained target (`a, b = command_group(...), command_group(...)`), a walrus (`(g := command_group(...))`), a call under an `if`, `try`, `with`, loop or `match`, a call inside a function, lambda, comprehension or class, and a call nested in another expression such as a decorator or call argument. It also covers a name-only call such as `command_group("ci")`, because `command_group` creates the group when none is registered, and a top-level assignment whose group name isn't a string literal. Before, toolr dropped such a group and every command on it without a word and exited 0. Give each group its own top-level `name = command_group("name", ...)` line (a keyword `name="..."` works too), and move any platform check into the command body. A call that isn't toolr's (`self.command_group`, a local `def command_group`) is never reported; only a function's or lambda's parameters named `command_group` shadow it, so another local rebinding inside a `def` is still flagged.
