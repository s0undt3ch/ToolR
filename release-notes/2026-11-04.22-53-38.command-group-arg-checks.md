`command_group()` now raises for contradictory arguments (such as passing both `docstring` and `description`) even when the group already exists, instead of silently returning the existing group. It no longer raises at runtime for a missing description: a title-only call, `command_group("ci", "CI")`, returns the group if it exists and creates it otherwise, and the manifest build checks that some declaration describes the group instead.

When several calls declare the same group, a later call fills a title or description the group still has empty (and, in Python, a long description), so `toolr <group> --help` and `CommandsTester` show the description whichever module gives it. A conflicting re-declaration, with a different non-empty title or description, keeps the first group: Python logs it at DEBUG level, and toolr warns when it rebuilds the manifest, naming both modules.
