**Breaking:** `toolr` and `CommandsTester` now refuse three shapes they used to read differently. A command name defined twice in one group, in one file or across files of one `tools/` tree or plugin package, fails with "duplicate commands" listing every definition (it used to keep one silently); rename all but one, e.g. with `name="…"`. A command decorator on a nested `def` (inside another function, a class or an `if`) and a `group=` or command name that isn't a string literal fail with "unsupported command declarations"; move the `def` to module level and write the value as a literal. A local command shadowing a plugin's, or two plugins defining one command, still only warn.
