Every `toolr project` and `toolr self` command now reports a missing project with the same message, `toolr: no toolr project found above <dir>`. `toolr project venv sync` and `toolr self build-manifest --package` used to wrap it in extra text.

The stale-manifest warning now shows what is wrong with the tools file, for example `Expected an identifier ... (line 2, column 5)`, instead of only its name. Parse errors report a line and column rather than a byte range.

A command that raises now prints a traceback that starts at your own code, without the toolr runner frames above it. `toolr -d` keeps the full traceback, as does an error inside toolr itself.

A control character in a tools file, such as an escape sequence, now shows escaped in the parse error instead of reaching your terminal.
