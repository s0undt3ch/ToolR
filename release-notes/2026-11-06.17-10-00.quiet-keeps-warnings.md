**Breaking:** `toolr --quiet` (and `-q`) no longer hides warnings. A `-q` run now prints these on stderr, where it used to drop them: skipped or shadowed plugins, manifest build warnings, the `toolr-py` version mismatch, the failed `meta.json` touch for a cache venv (an in-tree venv still needs `-d`) and the runner's unresolved-type warning. Scripts that run `toolr -q <command>` against a project with such a problem will see that output on every run. `--quiet` still drops success lines and advice, never errors, refusals or warnings.
