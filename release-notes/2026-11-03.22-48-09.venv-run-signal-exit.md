A child killed by a signal is now reported consistently. `ctx.run(...).returncode` is `-N` for a child killed by signal `N`, as with `subprocess` (it used to be `-1` for every signal). On Unix, `ctx.exit()` turns a negative status into `128 + N`, as a shell does, so `ctx.exit(result.returncode)` after a SIGTERM'd child exits 143 rather than 241. `toolr project venv run` and `toolr project venv shell` now exit `128 + N` for a signal-killed child instead of 1. An exit code that doesn't fit in a byte (Windows crash statuses, or 256) now makes toolr exit 1; it used to be truncated, and could turn a failure into exit 0.
