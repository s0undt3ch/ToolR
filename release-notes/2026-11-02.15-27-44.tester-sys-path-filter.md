`toolr.testing.CommandsTester` no longer keeps a repo on `sys.path` just because its path contains `site-packages` or `dist-packages`. A repo checked out under a directory such as `windows-site-packages` stayed on `sys.path`, so `discover()` could import that repo's own `tools/` instead of the test fixture's. Only the interpreter's own site directories, as `site` and `sysconfig` report them, are now exempt from the isolation.
