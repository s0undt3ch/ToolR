`ctx.run(..., capture_output=True)` keeps capturing when its streamed copy of the output can't be written, for example when toolr's output is piped into `head`. Both copies used to stop together, so the command was cut off and `result.stdout` came back truncated without a warning. A failure to write the captured output itself now raises `CommandError` instead of returning partial output.

A streamed copy that fails for any other reason, such as a full disk behind `toolr cmd > file`, raises `CommandError` too.
