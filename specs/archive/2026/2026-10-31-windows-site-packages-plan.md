# Windows Site Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `toolr self build-manifest <package>` finds packages in a Windows venv, and every site-packages lookup
goes through one helper (F-14).

**Architecture:** A new `toolr_core::venv::site_packages_dirs` lists the existing `lib/python*/site-packages` and
`Lib/site-packages` directories by reading directories, not globbing. `find_in_venv`, `glob_manifests`,
`locate_toolr_package` and `installed_toolr_py_version` all use it.

**Tech Stack:** Rust, `assert_cmd`.

**Spec:** [`specs/archive/2026/2026-10-31-windows-site-packages-design.md`](./2026-10-31-windows-site-packages-design.md)

## Global Constraints

- Both layouts are checked on every platform; no `cfg(windows)` in the helper or its tests.
- No globbing of a venv path anywhere after this change; F-07's bracketed-path tests stay unmodified and green.
- No schema change.
- Conventional Commits; no `Co-Authored-By`. Stage by path; never `git add -A`. `rustfmt <file>` on touched files only.

## Review Focus

1. **F-07 regression.** Bracketed, `*` and `?` venv paths must still work. Run F-07's tests unmodified in each
   task's verification step.
2. **Both layouts in one venv** (a venv copied between OSes). Both are returned, sorted; `find_in_venv` warns about
   more than one match. Task 1, `site_packages_dirs_returns_both_layouts_sorted`.
3. **Free-threaded `python3.14t`.** Task 1, `site_packages_dirs_finds_free_threaded_layout`.
4. **Upper-case `LIB`** (as some tools write it on Windows). Task 1, `site_packages_dirs_matches_lib_ignoring_case`.
5. **A plain file named `lib` or `site-packages`.** Not returned. Task 1, `site_packages_dirs_ignores_files`.

### Task 1: `site_packages_dirs`

**Files:**

- Create: `crates/toolr-core/src/venv/layout.rs`
- Modify: `crates/toolr-core/src/venv/mod.rs` (`pub mod layout;`, `pub use layout::site_packages_dirs;`)
- Modify: `crates/toolr-core/src/venv/validate.rs` (remove `candidate_site_packages`; callers use the helper)
- Modify: `crates/toolr/tests/project_venv_run.rs` (doc comment at ~98 names the new helper)
- Test: `crates/toolr-core/src/venv/layout.rs` `mod tests`

**Interfaces:**

- Produces: `pub fn site_packages_dirs(venv_dir: &Path) -> Result<Vec<PathBuf>, SitePackagesError>`. It returns
  existing directories only, sorted and deduplicated. A missing venv or `lib` is an empty list; an unreadable `lib`,
  `Lib/site-packages` or `pyvenv.cfg` Python's `site-packages` is an error.

- [ ] **Step 1: Write the tests:**
    - `site_packages_dirs_finds_unix_layout`: `lib/python3.13/site-packages` → `[that]`.
    - `site_packages_dirs_finds_windows_layout`: `Lib/site-packages` → `[that]`.
    - `site_packages_dirs_finds_free_threaded_layout`: `lib/python3.14t/site-packages` → `[that]`.
    - `site_packages_dirs_returns_both_layouts_sorted` (`#[cfg(not(any(windows, target_os = "macos")))]`, because
      it needs a case-sensitive file system): `lib/python3.12/site-packages`, `lib/python3.13/site-packages`,
      `Lib/site-packages` → all three, in sorted order.
    - `site_packages_dirs_matches_lib_ignoring_case` (case-insensitive file systems only): `LIB/site-packages` →
      `[Lib/site-packages]`.
    - `site_packages_dirs_ignores_files`: a file `lib/python3.13/site-packages` and a file `Lib` → `[]`.
    - `site_packages_dirs_empty_for_missing_venv`: non-existent dir → `[]`.
    - `site_packages_dirs_under_bracketed_venv`: venv at `tmp/[wip]/venv` with the Unix layout → found.

- [ ] **Step 2: Run** `cargo test -p toolr-core --lib venv::layout` → fails to compile.

- [ ] **Step 3: Implement** as the spec describes (`fs::read_dir`, `eq_ignore_ascii_case("lib")`,
      `starts_with("python")`, `is_dir()`, sort, dedup). Switch `locate_toolr_package` and
      `installed_toolr_py_version` over and delete `candidate_site_packages`.

- [ ] **Step 4: Run** `cargo test -p toolr-core --lib venv::` → PASS. Also
      `cargo test -p toolr --test project_venv_run` → PASS.

- [ ] **Step 5: Commit.** `refactor(venv): one site-packages locator for both venv layouts`
